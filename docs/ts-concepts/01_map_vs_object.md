# Map 映射 vs 普通对象映射

## 问题背景
在 TS/JS 中，"Map" 这个词容易混淆：
- `new Map()`：ES6 的哈希表数据结构
- 普通对象 `{}`：常被当作"映射"使用，但本质是属性存储

两者都能做"键值映射"，但底层实现、性能特征、键的语义都不同。选错会导致隐蔽 Bug。

## 本质区别
| | `new Map()` | 普通对象 `{}` |
|---|---|---|
| 底层 | 真正的哈希表 | V8 隐藏类 + 属性存储 |
| 键类型 | 任意值（对象、函数、原始值均可） | 只能是字符串 / Symbol（其他强转为字符串） |
| 大小 | `.size` — O(1) | `Object.keys().length` — O(n) |
| 插入顺序 | 严格保证 | 保证（ES2015+），但整数键会先排序 |
| 删除 | `delete` 高效 | `delete` 可能触发"字典模式"降级 |
| 迭代 | 原生可迭代 | 需 `Object.entries` 等 |
| 原型链 | 无 | 有（可能误判 `hasOwnProperty`） |

## 性能差异：V8 隐藏类
这是性能差异的根源：

- **普通对象**依赖 V8 的"隐藏类"优化。结构稳定时，属性访问通过内联缓存直接定位，非常快。但频繁动态增删属性会"降级"到字典模式，退化成哈希查找，反而比 `Map` 慢。
- **Map** 从一开始就按哈希表设计，没有"形状"概念，无论键怎么变，性能稳定。

### 什么时候谁更好
- 键少且固定（如 `{count:0, sum:0}`）：普通对象略快
- 键动态、数量大、频繁增删：`Map` 更优且语义清晰
- 需要非字符串键（对象、数组当 key）：必须用 `Map`
- 需要频繁 `.size` 或迭代：`Map` 明显占优

## 键类型陷阱（重点）
键的类型决定用哪个才安全。

### 1. 对象当键
```typescript
const a = { id: 1 };
const b = { id: 2 };
const obj: Record<string, string> = {};
obj[a] = '值1';  // 实际键变成 "[object Object]"
obj[b] = '值2';  // 覆盖了上一个！
console.log(obj); // { "[object Object]": '值2' }
```
普通对象用对象当键 → 强转成 `"[object Object]"`，所有不同对象变成同一个键，互相覆盖，**完全失效**。

而 `Map` 用对象当键 → 按**引用身份**区分，安全：
```typescript
const map = new Map();
map.set(a, '值1');
map.set(b, '值2');
map.get(a); // '值1' ✓
```

### 2. 数字当键
```typescript
const obj: Record<string, string> = {};
obj[1] = 'a';
obj['1'] = 'b';
console.log(obj); // { '1': 'b' }  数字 1 被强转为字符串 '1'，和 '1' 是同一个键
```
读写都走同一套强转规则，所以**频率统计**场景下用普通对象通常**安全**。
但若需要区分 `1` 和 `'1'`（数字键和字符串键并存），只有 `Map` 能做到。

## 判定原则
| 键的类型 | 普通对象 `{}` | `Map` |
|---|---|---|
| 字符串 / 数字 | ✅ 安全（但数字会转字符串） | ✅ 安全（保留原始类型） |
| 对象 / 数组 | ❌ 全变 `"[object Object]"` | ✅ 按引用区分 |
| 需要区分 `1` 和 `'1'` | ❌ 无法区分 | ✅ 可区分 |

## 进阶：引用相等 vs 内容相等
这是理解"对象当键"更深一层的概念：

- **引用相等**：两个变量指向内存里**同一个对象**才相等（`Map` 用的）
- **内容相等**：两个变量**内容一样**就算相等（哪怕内存里是两份）

```typescript
const a = { x: 1 };
const b = { x: 1 };  // 内容相同，但不是同一个对象
const map = new Map();
map.set(a, 'v');
map.get(b);  // undefined  ← Map 认引用，b 不是 a
map.get(a);  // 'v' ✓
```

如果需要"内容相同就当同一键"（如字母异位词分组），`Map` 也不够用，需要**哈希函数**把内容转成字符串键。详见 `algorithm-theory/07_hash_function.md`。

## 刷题实操建议
默认用 `new Map()`，原因：
1. 语义清晰，`get/set/has/delete` 意图明确
2. 不会踩 `obj[1]` 变 `obj["1"]`、原型链 `hasOwnProperty` 误判等坑
3. 频繁增删场景性能稳定

只有确认键是小整数、数量不大、且追求极致常数时，才用普通对象（如用数组下标当 key 的频率统计题）。

## 关键要点
- 选 Map 还是普通对象，**语义正确性比性能更关键**
- 对象当键：普通对象失效（强转字符串），`Map` 按引用区分
- 数字当键：普通对象安全但会转字符串，混合使用易踩坑
- 需要内容相等语义 → 需要哈希函数（非 Map/对象直接能解决）
